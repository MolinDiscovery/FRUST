# TS Guess DataFrames

The default catalyst-screen backend is `tsguess2`. It converts each expanded
substrate-catalyst system into a connected TS-like SMILES graph, embeds that
graph with role-coordinate anchors, and returns one initial FRUST dataframe per
requested TS family.

```python
import frust as ft

components = ft.screen.read("docs/examples/screen.csv")
systems = ft.screen.expand(components)

ts_guesses = ft.screen.create_ts_guesses(
    systems,
    ts_types=["TS1", "TS2", "TS3", "TS4"],
    n_confs=1,
)

ts_guesses.keys()
```

Output:

```text
dict_keys(['TS1', 'TS2', 'TS3', 'TS4'])
```

!!! info "The production backend is `tsguess2`"

    Both `ft.screen.create_ts_guesses(...)` and
    `ft.workflows.screen_ts(...)` use `tsguess2` by default. Generated rows
    record that choice in `tsguess_backend`, and v2 specification identifiers
    end in `_v2`.

    The original `tsguess` role-assembly backend remains available for
    compatibility. It has different construction rules and role names; do not
    use its output examples to interpret a default screen.


| --- | --- | ---: | ---: | --- | --- |

Important columns are:

| Column | Meaning |
| --- | --- |
| `custom_name` | Readable structure name used in plots and output directories |
| `structure_id` | Stable TS type, system, and `rpos` identifier |
| `structure_type` | `TS1`, `TS2`, `TS3`, or `TS4` |
| `molecule_role` | `ts` for generated transition-state guesses |
| `system_name` | Substrate-catalyst pair name |
| `rpos` | Substrate aromatic C-H atom selected for this row |
| `cid` | Embedded conformer identifier |
| `smiles`, `input_smiles` | Connected TS-like graph generated by `tsguess2` |
| `atoms`, `coords_embedded` | Atom order and starting Cartesian coordinates |
| `connectivity_bonds` | Graph connectivity used to reconstruct and draw the row |
| `constraint_roles` | Mapping from v2 chemical role names to row-specific atom indices |
| `constraint_spec` | Role-based distance and angle constraints |
| `constraint_atoms` | Compatibility projection for older fixed-order constraint paths |
| `tsguess_backend` | Backend that generated the row; normally `tsguess2` |
| `ts_spec_id` | Versioned built-in specification identifier |
| `ts_core_metrics` | Measured core distances/angles and deltas from the specification |

Conformer-generation provenance is stored in
`df.attrs["frust_conformers"]`. Backend-specific generation details, including
the generated SMILES and RDKit embedding options, are stored in
`df.attrs["frust_tsguess2"]`.

```python
ts1 = ts_guesses["TS1"]

ft.show_steps(ts1)
ts1.attrs["frust_tsguess2"]["backend"]
```

## How `tsguess2` Constructs A Guess

The default path is:

```text
expanded system + rpos
    -> connected TS-like SMILES
    -> explicit-hydrogen RDKit molecule
    -> SMARTS match for v2 roles
    -> coordinate map for reactive-core roles
    -> RDKit conformer embedding
    -> constraints, core metrics, and dataframe rows
```

For every system, reactive position, and TS family, FRUST:

1. Validates that `rpos` is an aromatic substrate C-H atom.
2. Builds a connected graph from the catalyst, substrate, and any required
   HBpin atoms.
3. Adds explicit hydrogens and recovers the reactive-core atom roles with the
   TS specification SMARTS pattern.
4. Creates an RDKit coordinate map from the role coordinates stored in the v2
   specification.
5. Embeds the requested conformers while keeping the reactive roles close to
   those coordinates.
6. Stores the connected graph, embedded coordinates, role map, constraints,
   and measured core geometry in each dataframe row.

`tsguess2` does not assemble disconnected fragments with the soft-frame-anchor
procedure used by the original backend. Its transferable unit is the generated
connected graph plus the v2 role-coordinate map.

## TS1-TS4 Roles

The four v2 specifications use these row-level roles:

| TS family | Main roles | Graph/geometry distinction |
| --- | --- | --- |
| `TS1` | `cat_B`, `cat_N`, `substrate_C`, `transfer_H` | Uses the N-bound hydrogen as `transfer_H` in the C-H activation coordinate map |
| `TS2` | `cat_B`, `cat_N`, `substrate_C`, `B_transfer_H`, `N_transfer_H` | Tracks separate B-bound and N-bound hydrogens for the H-H motif |
| `TS3` | `cat_B`, `pin_B`, `substrate_C`, `transfer_H` | Uses the B-H-B bridge graph with the TS3 role coordinates and constraints |
| `TS4` | `cat_B`, `pin_B`, `substrate_C`, `transfer_H` | Uses the same role names as TS3 but a different coordinate/constraint specification |

Role meanings:

| Role | Meaning |
| --- | --- |
| `cat_B` | Catalyst boron recovered from the generated graph |
| `cat_N` | Catalyst tertiary nitrogen used by TS1 and TS2 |
| `substrate_C` | Substrate carbon selected by `rpos` |
| `transfer_H` | Hydrogen assigned to the primary TS1, TS3, or TS4 transfer coordinate |
| `B_transfer_H` | TS2 hydrogen bound to catalyst boron |
| `N_transfer_H` | TS2 hydrogen bound to catalyst nitrogen |
| `pin_B` | HBpin boron used by TS3 and TS4 |

!!! note "TS3 and TS4 share role names"

    Their chemistry is distinguished by `ts_spec_id`, role coordinates, and
    `constraint_spec`, not by adding a `cat_H` role. Always interpret a row
    using both `structure_type` and its stored constraint specification.

## Inspect Row-Level Constraints

Inspect the roles before running a constrained optimization:

```python
row = ts_guesses["TS2"].iloc[0]

sorted(row["constraint_roles"])
```

Output:

```text
['B_transfer_H', 'N_transfer_H', 'cat_B', 'cat_N', 'substrate_C']
```

The atom indices are specific to that generated row. The constraints refer to
the role names instead:

```python
row["constraint_spec"]
```

Representative TS2 specification:

| kind | roles | value |
| --- | --- | ---: |
| distance | `['cat_B', 'B_transfer_H']` | 1.656 |
| distance | `['cat_N', 'N_transfer_H']` | 1.961 |
| distance | `['cat_B', 'cat_N']` | 3.080 |
| angle | `['cat_B', 'B_transfer_H', 'cat_N']` | 87.387 |

`constraint_roles` maps chemistry to indices. `constraint_spec` defines which
distances and angles an optimizer should render. This separation allows the atom
numbering to vary between systems.

!!! warning "Display bonds are not constraints"

    `connectivity_bonds` reconstructs the connected graph for storage and
    visualization. Constrained optimizers use `constraint_spec`; do not infer
    the constrained geometry solely from displayed bonds.

## Inspect Geometry Before Calculations

Always inspect a few generated rows before launching a screen:

```python
for ts_type in ["TS1", "TS2", "TS3", "TS4"]:
    ft.plot_row(ts_guesses[ts_type], 0)
```

For a compact panel:

```python
ft.plot_mols(
    ts_guesses["TS4"],
    row_indices=range(0, min(6, len(ts_guesses["TS4"]))),
)
```

Check that:

| TS family | Geometry check |
| --- | --- |
| `TS1` | The N-bound transfer hydrogen and selected substrate carbon occupy the intended activation geometry |
| `TS2` | The B-bound and N-bound hydrogens form the intended motif without severe clashes |
| `TS3` | Catalyst B, bridging H, HBpin B, and substrate C form the compact TS3 core |
| `TS4` | The same four roles follow the distinct TS4 distances and angles |

`ts_core_metrics` gives a numerical check against the stored specification:

```python
ts_guesses["TS3"].iloc[0]["ts_core_metrics"][:4]
```

| kind | roles | reference | measured | delta |
| --- | --- | ---: | ---: | ---: |
| distance | `['transfer_H', 'cat_B']` | 1.376 | 1.382 | 0.006 |
| distance | `['transfer_H', 'pin_B']` | 1.264 | 1.265 | 0.001 |
| distance | `['transfer_H', 'substrate_C']` | 2.477 | 2.482 | 0.005 |
| distance | `['cat_B', 'substrate_C']` | 1.616 | 1.616 | 0.000 |

Small core deltas show that embedding respected the coordinate map; they do not
prove that the structure is a valid transition state. Inspect the final
imaginary mode before using a barrier.

## Use The Rows With `Stepper`

Generated rows are self-describing, so constrained stages do not need fixed
atom indices:

```python
step = ft.Stepper(n_cores=8, save_output_dir=False)

ts4_preopt = step.xtb(
    ts_guesses["TS4"],
    name="xtb_preopt",
    options={"gfnff": None, "opt": None},
    constraint=True,
)
```

When `constraint_roles` and `constraint_spec` are present, `Stepper` renders
those row-level constraints. `constraint_atoms` is retained only for older
constraint paths and compatibility with existing data.

## Common Failures

| Failure | Meaning | Next check |
| --- | --- | --- |
| No catalyst boron | The catalyst SMILES does not contain the boron required by the builder | Check the exact catalyst SMILES and charge state |
| No matching tertiary nitrogen | TS1/TS2 could not find the supported catalyst amine motif | Confirm that the catalyst matches the current TS1/TS2 builder scope |
| Invalid `rpos` | The requested atom is not an aromatic C-H in the parsed substrate | Draw labels from the exact substrate SMILES |
| Generated SMILES cannot be parsed | The requested graph is chemically invalid for the supplied components | Inspect valence, formal charges, and whether the motif applies |
| Core SMARTS does not match | The generated graph is outside the current v2 specification | Reproduce one system with the matching public `ft.tsguess2` builder and inspect its returned SMILES |
| No embedded conformers | RDKit could not embed the anchored graph | Retry a single target and inspect the generated graph and role coordinates |

The current production guidance is to extend `tsguess2` with dynamic graph and
role assignment. Do not add fixed atom-index logic for new chemistry.
